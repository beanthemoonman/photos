## What this is

A small Spring Boot web app that serves a photo gallery from a directory on disk. No database — photos are read straight from the filesystem and thumbnails are cached as files.

## Commands

```bash
./mvnw package          # build (jar in target/)
./mvnw test             # run all tests
./mvnw test -Dtest=PhotoServiceTest                 # single test class
./mvnw test -Dtest=PhotoServiceTest#methodName      # single test method
./mvnw spring-boot:run  # run locally on :8080

docker build -t photos-app .
docker run -p 8080:8080 -v /path/to/photos:/app/photos photos-app
```

Java 25, Spring Boot 4.0. CI (`.github/workflows/build.yml`) runs `package` then `test`.

## Configuration

All config is in `application.properties` and overridable via env vars (see `docker-compose-example.yml` for the full set). Bound to `PhotosConfig` under the `photos.*` prefix:

- `photos.directory` (`PHOTOS_DIRECTORY`) — source photo dir, defaults to `photos/`
- `photos.thumbnail.width`/`height` — thumbnail box (aspect ratio preserved)
- `photos.website.*` — page title and OpenGraph metadata

`.env` / `.env.properties` is imported if present.

## Architecture

Request flow: `WebController` serves the Thymeleaf `index.html` shell; the page's `gallery.js` then drives everything via the JSON/image API under `PhotoController` (`/api/photos`).

- **PhotoService** — the core. Lists image files from `photos.directory` (sorted newest-first by mtime), paginates, and resolves photos by filename. Lookup falls back to matching the name without extension if the exact filename misses.
- **ThumbnailService** — wraps the `thumbnailator` library to produce a JPEG thumbnail from a source image. Reads the source's header dimensions first; very wide panoramas (aspect ratio > 2.4) get a 4× larger thumbnail box since they render full-gallery-width on the page. Note: cache keys are the source SHA, so existing thumbnails don't re-render on a sizing change — clear `cache/` to regenerate.
- **ThumbnailHasher** — the thumbnail cache. Maps each photo to a SHA-256 of its bytes (in-memory `shaCache`), and stores thumbnails on disk as `cache/<sha>.jpg`. Content-hash naming means edited photos get fresh thumbnails automatically. `ThumbnailHasherRunner` (a `CommandLineRunner`) calls `boot()` at startup to pre-generate the whole cache.
- **FileFilter / Utility** — static helpers: image extension filtering (`.jpg/.jpeg/.png/.gif`) and SHA-256 hashing.

`PhotoController` serves three things per photo: metadata (`/api/photos/{id}`), `/thumbnail` (cached, `Cache-Control` 1 day), and `/full` (raw bytes). The front end uses infinite scroll and a click-to-zoom modal with browser-history integration.

### Git version display

`GitInfoService` reads build-time `git.properties` (generated by the `git-commit-id-maven-plugin`) and the commit hash is shown in the footer. **This is why the Dockerfile copies `.git` into the build stage** — without it the plugin can't generate the file. Values fall back to `"unknown"` if absent.
